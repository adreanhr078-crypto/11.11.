# Fix Plan: Puzzle Constants, Story Acts, and Memory Shard Counts

## Context

The project has moved to a manual puzzle system (`puzzleLoader.ts`) with **400 authored puzzles** (4 batches × 100). However, several global constants, story act definitions, achievement thresholds, and memory-shard references still assume the old generated system of **1000 puzzles across 7 acts**. This causes runtime throws, incorrect achievement triggers, and mismatched progress indicators.

## Issues Found

1. **Duplicate `TOTAL_PUZZLES` exports**
   - `constants/puzzleConstants.ts:9` exports `1000`
   - `core/puzzles/puzzleLoader.ts:13` re-exports `ALL_MANUAL_PUZZLES.length` (= 400)
   - `stores/gameStoreHelpers.ts:14` imports the 1000 value
   - Result: `totalPuzzles` in initial state is 1000 while only 400 puzzles exist.

2. **Stale `ORIGINAL_PUZZLE_COUNT`**
   - `constants/puzzleConstants.ts:8` is `219`
   - Actual authored count is 400
   - `stores/gameStoreHelpers.ts:276` uses it for `all_puzzles` achievement → never unlocks correctly.

3. **`storyActs.ts` defines only Act 1**
   - `STORY_ARCS` contains one act: `[1, 100]`
   - `core/puzzleGenerator.ts:1442` loops `i = 1..1050` calling `getActByPuzzleNumber(i)` → throws `"No act found for puzzle X"` for `i > 100`.
   - `core/puzzleLazyGenerator.ts:85,164` does the same.
   - These generator files are imported by no live runtime code, but the export surface is public and risky.

4. **`BATCH_SIZE = 50` mismatch**
   - `core/puzzles/puzzleLoader.ts:14` uses `BATCH_SIZE = 50`
   - Each batch file (`batch_01..04.ts`) has 100 puzzles
   - `getPuzzleBatch(1)` returns only the first 50.

5. **Achievement thresholds assume 1000 puzzles**
   - `stores/gameStoreHelpers.ts:299-305` uses `150/300/450/600/750/900/1000`
   - With 400 puzzles these will never unlock correctly.

6. **`puzzleLazyGenerator.ts` is dead code**
   - No external imports of its `generatePuzzle` or `isAnswerCorrect`
   - Imported only by itself from `puzzleGenerator.ts`
   - Should be removed to reduce maintenance confusion.

7. **Triplicated `isAnswerCorrect`**
   - `puzzleGenerator.ts:1406`, `puzzleLazyGenerator.ts:133`, `puzzleLoader.ts:97`
   - Only `puzzleLoader.ts` version is used live; others should be removed.

8. **Memory shard constants mismatch**
   - `constants/puzzleConstants.ts:35` exports `TOTAL_MEMORY_SHARDS = 219`
   - Actual shard count in `core/memoryShardsSystem.ts` is different.
   - `stores/gameStore.ts:43` sets `totalFragments = puzzles.length` (= 400) instead of aligning with shards.

## Proposed Changes

### 1. Centralize puzzle counts in `puzzleConstants.ts`

- Update `ORIGINAL_PUZZLE_COUNT = 400`
- Update `TOTAL_PUZZLES = 400`
- Update `TOTAL_MEMORY_SHARDS` to actual count after shards are finalized (placeholder `400` until verified)
- Add documented comments that these are the authoritative values.

### 2. Update `storyActs.ts`

- Add Acts 2–7 with correct `puzzleRange` matching the manual batches:
  - Act 1: `[1, 100]` awakening
  - Act 2: `[101, 200]` discovery
  - Act 3: `[201, 300]` connection
  - Act 4: `[301, 400]` truth
  - Act 5: `[401, 500]` fracture
  - Act 6: `[501, 600]` vengeance
  - Act 7: `[601, 700]` finale
- Keep descriptions in Arabic and English consistent with existing narrative.
- Ensure `getTotalPuzzleCount()` returns the configured total.

### 3. Fix `puzzleLoader.ts`

- Set `BATCH_SIZE = 100` to match actual batch files.
- Remove local re-export of `TOTAL_PUZZLES` and import it from `puzzleConstants.ts` instead.

### 4. Fix `gameStoreHelpers.ts`

- Import `TOTAL_PUZZLES` and `ORIGINAL_PUZZLE_COUNT` from `puzzleConstants.ts` (already imported; values just need updating upstream).
- Update act-completion thresholds to match 400 total:
  - Act 1: 100
  - Act 2: 200
  - Act 3: 300
  - Act 4: 400
  - (Extend if more acts are added later)
- Add explicit guards so undefined act lookups do not throw.

### 5. Remove dead code `puzzleLazyGenerator.ts`

- Delete the file entirely.
- Remove any remaining imports referencing it.
- Keep `puzzleGenerator.ts` only if its templates/helpers are used elsewhere; otherwise remove as well. Verify via search first.

### 6. Remove duplicated `isAnswerCorrect` from `puzzleGenerator.ts`

- Keep the canonical version in `puzzleLoader.ts`.
- Delete the function from `puzzleGenerator.ts` and `puzzleLazyGenerator.ts`.

### 7. Align memory shard count

- After the new 100 shards (501–600) are added in `memoryShardsSystem.ts`, update `TOTAL_MEMORY_SHARDS` in `puzzleConstants.ts` to the new total.
- In `gameStore.ts:43`, set `totalFragments = TOTAL_MEMORY_SHARDS` instead of `puzzles.length`.

### 8. Test and validate

- Run TypeScript typecheck: `cd artifacts/eleven-eleven && npx tsc --noEmit`
- Run tests if vitest is configured; if not, add smoke test script.
- Verify `getActByPuzzleNumber(400)` returns Act 4.
- Verify `getPuzzleBatch(4)` returns 100 items.

## Open Questions

1. Should `puzzleGenerator.ts` be fully removed, or do any UI/tools still import its templates? (Search repo for imports first; recommend delete if unused.)
2. Do we keep the `actX_complete` achievement thresholds hardcoded, or derive them dynamically from `STORY_ARCS` ranges? (Recommended: derive dynamically.)
3. Should `puzzleConstants.ts` keep `TOTAL_PUZZLES = 400` or compute it from `storyActs.ts` end-range? (Recommended: single source in `puzzleConstants`, mirror in `storyActs`.)

## Validation Plan

- `npx tsc --noEmit` passes.
- All 400 manual puzzles load without undefined.
- `getActByPuzzleNumber` returns valid acts for 1–400.
- `shard_master` achievement logic uses correct total.
- No import errors from deleted files.
