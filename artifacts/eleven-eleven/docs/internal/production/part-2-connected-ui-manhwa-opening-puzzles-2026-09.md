# 11.11 — خطة المرحلة الثانية: الرحلة المتصلة

**المرحلة:** `PART_2_CONNECTED_UI_MANHWA_AND_OPENING_PUZZLES`  
**الحالة:** `IN_PROGRESS`  
**التاريخ:** 2026-09-04  
**المرجع:** المرحلة الأولى المعتمدة، `docs/project-memory.json`، مصفوفة
`part-1-opening-vertical-slice-matrix-2026-09.md`، وCanon Manhwa المعتمد.

## الهدف

تحويل الشاشات الموجودة من نقاط منفصلة إلى حلقة قصة مفهومة وقابلة للاستئناف:

`Mission Control → Manhwa → opening Story Puzzle → server receipt → Echo
response → truthful next objective`

لا نضيف Canon جديدًا في هذه المرحلة. القيمة المطلوبة هي أن يفهم اللاعب لماذا
ينتقل، ماذا تغيّر بعد قراره، وما الفعل التالي الذي يقوده إليه النظام.

## نطاق التنفيذ الحالي

- جعل شاشة إيصال المكافأة وشاشة اللغز المكتمل تستخدمان `CorePlayerObjective`
  نفسه بدل زر ثابت يفترض أن الوجهة التالية هي Manhwa دائمًا.
- مطابقة نص الزر وأيقونته ومساره لنوع الهدف: قراءة Manhwa، حل لغز/فحص شظية،
  أو فتح الأرشيف بعد اكتمال المسار الأساسي.
- إبقاء المكافآت والتقدم وفتح القنوات خلف إيصال الخادم الحالي؛ العرض لا يمنح
  Receipt ولا يعيد طلبه.
- إضافة اختبار انحدار يثبت أن مسار ما بعد المكافأة لا يعود إلى زر Manhwa
  ثابت، وأن حالات `read/solve/complete` ممثلة بصريًا وقابلة للوصول.

## حدود المرحلة

- الصفحات المكشوفة تبقى ضمن مصفوفة الصفحات 1–9؛ الصفحات 10–70 لا تُفتح.
- لا Screen Break، ولا أول بيئة 3D، ولا Guide، ولا Transformation، ولا Combat.
- لا تعديل على Canon أو الألغاز المجمدة أو `src/domain/cinematics/`.
- لا نشر Cloudflare أو تفعيل R2 أو Realtime Worker.
- الافتتاحية Blender/WebM تبقى Previsual/Promotional فقط، ولا تمنح تقدمًا أو
  مكافأة ولا تحل محل مسار اللعب.

## بوابة قبول المرحلة الثانية

1. كل حل Story Puzzle ناجح يمر عبر receipt سلطوي واحد، ثم يعرض المكافأة، رد
   Echo، والهدف التالي.
2. زر المتابعة يفتح الوجهة الصحيحة للهدف الحالي في العربية والإنجليزية؛ لا
   توجد تسمية أو أيقونة Manhwa مضللة عند الانتقال إلى لغز أو أرشيف.
3. refresh/resume، loading/error/retry، keyboard/touch، mute، reduced motion،
   و390×844 و1280×800 لا تكسر الحلقة أو تخفي الفعل التالي.
4. اختبارات المحتوى، TypeScript، الاختبارات الكاملة، build، media، Worker
   dry-run، وpostflight تمر. أي قياس Edge أو INP/TTI/FPS غير متاح يبقى
   `UNVERIFIED`.
5. تُجرى مراجعة Playtest جديدة بعد اكتمال الربط، ولا تُستخدم هذه المرحلة
   لإثبات أن اللعبة ممتعة جدًا دون جلسة لاعب حقيقي أو قياس runtime مناسب.

## الخطوة التالية المسموح بها

والبيئة ثلاثية الأبعاد الأولى، مع عقد منفصل للتخطي، Reduced Motion، التحميل،
والعودة الآمنة إلى مسار اللاعب.
